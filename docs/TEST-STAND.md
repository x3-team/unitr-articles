# Тестовый выкат раздела «Статьи» на хостинг Reg.ru (до апрува заказчика)

Хостинг: shared Reg.ru «Хост-1», Apache + `.htaccess`, PHP 8.2, Node.js v10 (Next.js на хостинге не запустить).
Поэтому раздел работает по **варианту Б** из [RUNBOOK.md](RUNBOOK.md): HTML раздела пререндерится из WordPress
(GraphQL, токен только при сборке) в GitHub Actions и выкладывается по SFTP; 301/404/заголовки — правилами `.htaccess`;
обновление — каждые 10 минут по расписанию и сразу по сигналу из WordPress. Схема проверена на настоящем Apache
поверх SPA с fallback на `index.html` (`tests/e2e/run-apache-e2e.mjs`, 54/54).

**Боевой `www/unitr.ru` на шагах 1–10 только читается** (копия SPA для стенда). Выкладка на прод в workflow
заблокирована, пока не задано `vars.PROD_APPROVED=yes`.

Тестовые статьи в рубрике `poleznye-stati` публикуются, только если разведка покажет, что текущий SPA эту рубрику
не выводит (иначе они появятся на боевом сайте) — в этом случае отдельное согласование.

## Что именно меняется в `www/<сайт>` при выкладке раздела

- `articles/` — новый каталог, целиком принадлежит разделу (HTML страниц, `_media/`, свой `.htaccess`);
- `sitemap.xml`, `sitemaps/` — карта сайта (раздел + страницы SPA из `SITE_STATIC_PAGES`);
- `robots.txt` — заменяется (правила сайта переносятся через `ROBOTS_EXTRA`), исходный сохраняется как `robots.txt.before-unitr-articles`;
- `.htaccess` — в начало вставляется блок `# BEGIN unitr-articles … # END unitr-articles` (301 со `/blog`, `/poleznye-stati`,
  тип и кеш sitemap/robots); правила SPA ниже блока не меняются; исходный — `.htaccess.before-unitr-articles`;
- `index.html`, `assets/` и остальные файлы SPA **не трогаются**.
